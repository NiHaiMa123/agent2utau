## 1. 用户目标与本轮范围

用户当前使用 `singing-expression-editor` Skill 驱动 Codex 制作 OpenUtau 工程，反复遇到：新歌音高主体很平；要求学习人工工程后变成搬运参考曲线；下一首又退回平直。

本轮要补齐一套实际参与制作的复检流程，使遗漏、执行错误和缺乏依据的默认决策能在交付前暴露。保留“Agent 根据当前歌曲判断，函数负责准确执行”的方向；不改成固定模板派发，也不把每个字都画成波浪。

用户希望接近人工调校的工作步骤：理解整句意图，具体到每个字观察条件、选择处理、检查实际结果，再回到句内比较和修订。当前执行 Agent（包括选用 GPT-6.1-Sol 时）负责这些选择；脚本负责计量、执行与查漏。更换模型、写出详细解释或生成整曲总览，都不能替代逐字完成工作。记录简短依据、备选和处理结果即可，不以长篇思考文字作为验收证据。

用户让 Codex 拉取本文执行时，应完成必要的接口、检查器、测试及 Skill 接入，不停在扩写说明或新增几个禁止词。当前任务是本轮授权的补全范围；旧 `plan.md` 的 P0/P1 停止条件仍保留为历史实验边界，不自动恢复那些实验，也不阻止本轮完善复检。既有歌曲的听感接受、失败和 unknown 不因本轮改动而重写。

本轮不训练模型、不建立大型自然度评分系统、不重做全套歌曲流水线、不自动修复或覆盖所有旧工程。音频、模型、缓存、详细 run 产物继续留在本地，遵守 AGENTS.md。

## 2. 已核实的问题与能力边界

执行前复核当前本地实现；若代码已变化，按事实更新差异，不机械套用旧结论。

| 已有能力 | 尚需补齐的部分 |
| --- | --- |
| Skill 已要求逐元音判断和禁止搬运作者路线 | 将要求绑定到真实元音身份和生产执行入口，防止一句泛泛描述覆盖整句 |
| `design_functions.py` 验证字段、支撑、函数和局部幅度期待 | 自填期待只能验证执行一致性，不能证明该段选平稳是否合理 |
| `compile_functions` 检查乐句覆盖、原生读回和音素几何 | 默认入口尚未逐元音核对音乐决策及主体阶段是否漏做 |
| 独立 evaluation v0 已可描述平台、漂移、有限运动、周期和边界候选 | 将独立测量接入制作复检；形态描述仍不等于自然度判决 |
| 文档禁止作者数组用于生成，已有部分输入限制 | `origin: agent_designed` 只是声明；需审查调用代码、数值来源和研究到制作的边界 |
| 已有研究资料、条件配方和局部修订经验 | 需要前向决策和新歌验证，不能用同一首的反复修补证明迁移 |

本次审查用现有函数辅助工具验证：1.5 秒、1501 个采样点的完全常值线，在选择 hold 且期待幅度为 0 时通过；同一条线将期待改为 30～70 音分则失败。此实验没有运行 OpenUtau 或试听。它证明辅助工具按声明工作，不能据此认定合法平稳音应被禁止。

### 2.1 用户图示与当前表达能力

用户于 2026-10-15 提供钢琴卷帘截图，强调各字曲线应有可辨别的形态差异。本要求将图中可观察特征写在下表，后续执行不依赖取得该聊天附件。截图只有外观，缺少可靠时间刻度、完整工程与对应声音；以下是形态观察，不是对作者意图或实际听感的鉴定。

| 图示中可观察的形态 | 当前可以使用的表达方式 | 需要核对的限制 |
| --- | --- | --- |
| 一个字的主体内有浅弯折、缓慢升降及回收，而非全程同一水平线 | `design_functions.py` 的多节点 `center_nodes`，节点含绝对音高与斜率 | 不能把所有内部节点省成两个等值端点；慢中心变化本身可有意义，不必另加颤音 |
| 换字附近有下探、上挑或到达后的回收，下降和恢复时长不同 | 同一 helper 的有符号 `finite_return`，独立指定开始、峰值和结束；也可由中心节点描述连接 | 动作须落在当前实际支撑与前后关系内；辅音/非唱区的低谷不能冒充字腹表达 |
| 连续峰谷的高度、间隔和方向不一致，部分字仅有一次有限动作 | 多个中心节点与有限动作组合；`context_actions.py` 的 `body_landmarks`、`periodic_landmarks`、`sparse_enveloped_route` 等可显式表达更细路线 | 单个规则正弦不能代表任意不对称走势；更丰富接口与默认 helper 的 schema 不相同，须验证实际调用与原生转写 |
| 有的区域较平稳，有的在后部展开或退出，局部密度不同 | 分段选择 hold、有限动作、变深变速 `oscillation` 及独立进入/退出包络 | 按当前字选择，不统一给每字派发同形波浪，不用随机扰动制造差异 |
| 蓝色音符之间的大幅上下移动 | 所选旋律及音符衔接，加上实际连续目标线 | 先分清旋律音程和相对主音的表达偏移；整句音域大不代表每个字调得细 |

代码依据：[默认函数 helper](../skills/singing-expression-editor/scripts/design_functions.py)、[上下文动作执行器](../src/agent2utau/expression/context_actions.py)、[连续曲线组件](../src/agent2utau/expression/curve_components.py)、[包络化稀疏节点](../src/agent2utau/expression/enveloped_landmarks.py)、[整曲编译入口](../src/agent2utau/workflow.py)。

本次另用实际 helper 做了纯函数合成探针：不对称下探的下降 0.2 秒、恢复 0.5 秒及 -55 音分峰值被保留；另一条自行构造的路线保留了 8 个不同高度/时刻的节点和到达后 40 音分的回收。这些数值只用于验证表达能力，既非从截图读出，也不是新歌默认参数。本机运行环境缺少 pytest，未完成仓库测试套件；未写原生工程或渲染、试听新歌。

结论分三层：**现有函数能表达这些类型的形状；当前 Skill 和默认流程不能保证 Agent 会逐字选择并使用它们；本次没有证明这样的设计已在一首新歌中取得所需听感。** 不应先重写全部数学工具，也不能仅因函数存在就宣布问题解决。

用户的形态偏好应转化为“有上下文依据、可以辨认的字内过程和字间处理”。不设“大幅度就是高水平”的规则：不必要的夸大可能破坏主音、咬字和连贯性；某个字保持平稳也可能合理。不得临摹截图像素、拟合整串峰谷，或把看似细碎的痕迹全部当成应复制的演唱动作。

## 3. 不得采用的通过方式

1. 不以“曲线有非零点、控制点很多、整曲音域大、平均频率正常、跟随自身目标准确”证明字腹表达充分。
2. 不以一段字头滑音或字尾换音的大运动，替代主体内部运动的检查。
3. 不把“所有字都必须颤音、平稳段不得超过某比例、每字至少若干峰谷”设为通用音乐标准。不得随机加抖动过检查。
4. 不因原曲周期检测失败就默认画平线；也不把未知区补成周期后称为原曲事实。
5. 不把作者曲线裁剪、移调、重定时、稀疏拟合或改写成函数参数后称为独立学习成果。研究授权不自动变成复刻任务。
6. 不在看到失败后，只缩小检查窗口、降低期待、改源掩码或放宽阈值使同一结果通过。确有音乐判断修订时保留前后依据、数值和复检。
7. 不用改名后的旧歌曲脚本、旧缓存或未登记的直接 USTX 写入路径绕过复检。
8. 不将 Agent 的文本自评、数学检查、图像观察或频谱代理冒充实际试听；未听明确记录。
9. 不将“缺资料、未检查、unsupported”计为通过；同时不把缺少听感标签变成必须等待用户批准才可交付初版的流程。
10. 不为修复本轮问题删除身份、时钟、来源和原生检查；不为了凑完成而恢复已经撤出的参考模板路线。

## 4. 复检流程

### R0：确认实际执行版本与入口

先记录本地分支/commit、工作区修改、当前任务范围和目标歌曲。保护未提交改动及现有工程，不强制 reset、不覆盖用户本地版本。

定位 Codex 实际使用的 Skill：仓库路径、安装/链接路径、能够观察到的运行入口及文件 SHA。仓库 Skill 与安装副本不同必须说明；按当前安装机制同步所需改动并核验。磁盘副本相同不等于当前会话已加载新内容；无法核实会话加载状态时标为 unknown，不伪造“已生效”。

列清本次使用的 CLI、生成脚本和写入工程的路径。脚本是可复用入口还是历史单曲记录必须明确。优先接通通用入口；实际使用的自定义脚本必须调用同一复检契约，或明确标为未受完整审查的实验输出。

### R1：从当前输入建立独立的条件清单

先读取当前原曲观察、所选谱面、歌词、段落/重复关系和目标声库的原生音素时钟，再填写动作计划。条件清单绑定源文件、工程、导出、时基和软件/声库身份；源事实、工作解释、艺术选择分开记录。

以真实 part/phrase/note/phone 身份建立可枚举的元音组清单：

- 同一元音跨音符可作为一个发声单元，保留其内部有意义的音乐换音；同音换字不能误并为同一次发音。
- AP/SP、辅音、非唱前导/尾帧、身份有歧义区域单列，不能混进字腹运动分母。
- 记录前后音程、目标到达、实际可用主体、后续换字/停顿、源运动可靠性及相关语境。
- 元音阶段按实际音乐过程划分，不强制每个短字都分成四段，也不按统一时值百分比分割。
- 分母来自实际输入清单，不能由 Agent 已写出的决策条数反向决定。全部区域都有已处理、unknown 或不适用的明确归属。

没有原生环境时只建立能证明的 note-only 静态清单，不伪造元音边界；相关能力维持 static_only。

### R2：逐元音作出可追溯的动作选择

每个可识别元音组及其有意义的阶段，都必须映射到具体决策。允许跨多个元音共享一个动作，但必须列明各自身份、作用范围及共享原因；不能用整句一句“克制”替代逐项处理。

最小字段如下；字段名可按实际接口调整，但含义不可省略：

| 内容 | 必须表达的信息 |
| --- | --- |
| 身份与锚点 | 当前 part/phrase/note/phone IDs、绝对秒与原生锚点、所覆盖音乐阶段 |
| 当前条件 | 可定位的输入证据、前后关系、可靠性；观察与艺术选择的区分 |
| 选择及备选 | 动作目的、所选函数或 hold、一个在当前条件下合理的备选及拒绝依据 |
| 执行映射 | 实际 component/control IDs、参数、单位、支撑；由中心节点实现时也给出映射 |
| 局部期待 | 到达/转向顺序、主体运动位置、适用的幅度/时距/进入退出；不强制给不适用动作编造周期 |
| 不确定与状态 | unknown/unsupported、参数依据、planned/compiled/native_checked 等实际状态 |

平稳、短促直达、没有周期都可以是有效选择。hold 应说明当前字为何保持、怎样接前后字，并检查主音到达和退出；“短字一律平”“不确定所以平”“反正克制”不能直接结束复检。

生成前保存计划版本及哈希。修改选择时追加修订及原因，不能事后重写原计划制造“原本就打算这样”。

### R3：检查函数和最终工程是否真正执行了选择

保留现有数学、范围、时钟和原生读回检查，并增加：

1. 条件清单、决策、函数组件、原生输出之间可追溯；查漏项、重复归属、无效锚点、未使用参数和静默降级。
2. 检查最终绝对线，分开 note.pitch、before-PITD、PITD 和内置 vibrato 的贡献；不能只看 PITD 一条线推断实际音高。
3. 分别测到达、主体、释放；主体检查窗绑定 R1/R2 的有效支撑，不能自动挑最容易通过的窗口。
4. 对有要求的动作核验实际顺序和存在区，如先下探再回收、维持后展开、周期渐隐、同元音相位延续、换音到达；单个 max-min 不能替代顺序核验。
5. 同时保留原始运动、慢中心走势和适用的去趋势残差。缓慢弯折、有限回收不因没有稳定周期而被判为平直失败。
6. 从函数目标到原生最终线的变化要可解释；检查叠加抵消、量化消失、过窄支撑、旧主体干扰和边界风险。多相位/实际渲染帧未检查时如实标记。
7. 只给适用项执行检查；短支撑不足以辨认周期时输出 unknown/不适用及依据，不硬凑峰谷，也不顺带取消其它可检验项目。

原有函数 helper 仍允许常值设计。语义覆盖与音乐选择复检应放在制作层，不能通过全局禁止常值去修改数学工具的正确行为。

### R4：独立测量，再审查选择是否有依据

采用两步复检，不要求引入另一个模型或多 Agent：

**第一步只看独立输入与实际产物。** 使用当前工程/原生导出、真实区域清单和固定配置提取形态及覆盖；此阶段不读取生成计划的 expectations 作为好坏真值。复用 evaluation v0，必要时扩展局部形态字段，不重复建设整个评价系统。

**第二步再对照原计划和当前音乐条件。** Agent 审阅独立事实，解释选择与实际形态是否一致，以及是否出现普遍默认化。审阅应引用真实区域和数值，记录采取的处理；同一 Agent 复检属于过程复检，不宣称独立人类听觉评审。

必须覆盖以下情况：

| 情况 | 处理 |
| --- | --- |
| 元音组或必要阶段没有决策，或承诺动作未实际执行 | 客观执行失败；修正后复检，不能标整曲执行完成 |
| 字头/尾部有大运动，但主体期待的运动没有出现 | 定位主体范围的执行失败；不能用整字音域抵消 |
| 已明确选择平稳，主音/连接正确，当前条件有具体依据 | 允许通过执行复检；不因此宣称自然度已验收 |
| 大量主体默认平稳、理由重复，或当前证据与选择不符 | 触发选择依据复审，列出相关区域及代表反例；不能仅填写“已复检”关闭 |
| 短支撑、源不可靠、原生身份或采样不足 | 保留 unknown，说明影响；不得计作通过 |
| 动作存在、执行正确，但是否合适缺乏听感证据 | 标记音乐效果未证实；不随机加波或统一放大 |

平稳比例、动作分布、相似形状、参数重复可作为复审线索，不能设置“达到某个波动比例就好听”的门槛。重复句可以相同；其差异也不能为了提高分散度而随机制造。

发现选择依据不足后，输出“补充了什么当前证据、保留或改动哪个决定、为什么”。确定性的程序检查不能证明这段文字的音乐判断必然正确，应保留该能力边界。

### R4.1：整曲总览之后，必须完成全曲逐字局部审阅

全曲总览用于判断段落、句势和整体覆盖；不能代替每个字的局部判断。原 Skill 中“查看浅/明显/平稳的代表细图”只够补充举例，必须在实际制作入口中升级为以下流程：

1. **按乐句分批，覆盖全曲。** 使用 R1 的真实清单建立字/元音组与音符、音素的对应。一个字跨多个音符时保留完整发声过程；同音换字分别审阅。先查看本句，再处理其中每个字及其前后衔接，最后回看本句。不能只做几句示范，把其余记成已检查。
2. **每个字都有可读的局部视图。** 视图应包含该字完整有效支撑，以及理解进入和退出所需的相邻字或停顿；不能仅裁一个字腹峰值。短字可共用清晰的邻接窗口，但逐字记录观察；长字/连音超过单页时用有重叠的连续视图覆盖全部过程。固定 2 秒切页只是显示默认，不是音乐边界。
3. **看到的是当前实际最终线。** 图册绑定工程、原生导出、时钟和生成版本，标注歌词/身份、音符目标及已核实的音素/阶段边界。区分函数设计图、原生读回图和实测 F0；没有原生数据时只标设计或静态检查，不能假装最终工程已核实。
4. **保留可比较的物理尺度。** 局部主视图使用声明且一致的像素/秒和像素/半音比例；允许平移纵轴、增加有刻度的细节或去趋势辅图。不要把数百字压到一张缩略图，或每字自动拉伸到相同振幅。需要放大时显示比例并保留标准视图；审阅端也须能读到细部。
5. **实际查看并逐字作出判断。** 执行 Agent 必须打开这些可读视图，并结合程序测得的数值，检查当前字的到达、主体、准备/退出以及相邻连接。分别指出哪里保持、哪里改变、是否符合该字条件，给出保留或修改的简短理由。幅度、时距、峰谷位置由数据计量，不能凭截图估读成精确事实。
6. **区别“生成了图”与“已经审阅”。** 每条记录绑定真实字/元音 ID、视图 ID、覆盖范围、输入/输出哈希、审阅方式及结果；图像查看与仅数值检查分别记录。只生成图册、只读总览、只写一个 `reviewed=true` 或套用相同评价句，不能证明逐字完成。工具访问记录可证明打开过某个视图，不能证明音乐理解正确。
7. **修改后复查受影响关系。** 重编译/后处理后重新取得实际线，更新有关字、前后连接和所属句子的检查；原生预测影响范围扩大时按实际依赖扩大。只有依赖与内容保持且可证明时才复用无关字的记录，不凭旧文件名沿用结论。
8. **报告覆盖分母与缺口。** 列出全曲可识别字/元音组总数、已完成局部审阅、待处理、失败、unknown 和不适用项及定位。明确漏看或缺阶段视图是覆盖缺口；无法确认审阅的记录保留 unknown。没有完成全曲局部覆盖，不得声明逐字复检已完成；仍可交付标明缺口的候选供继续处理。

现有 [contour_viewports.py](../skills/singing-expression-editor/scripts/contour_viewports.py) 已提供固定物理尺度的图册和坐标元数据，可作为基础；它不自动按字建立上下文、不记录 Agent 实际看图，也不作表达验收。应补身份映射、可读视图、审阅记录与覆盖检查，不能把该脚本运行成功当成本节完成。

每个字重点核对的不是“波浪够不够多”，而是：当前主音怎样到达、主体为何维持/变化、转折落在哪里、怎样接下一字；同一句内的处理是否随实际条件变化。音高线以外的音素时序、声线及发声控制仍需复检。图形通过不能替代对应声音的证据；有可用感知工具时结合局部上下文试听，没有时明确未听，不要求用户逐字批准才能继续制作。

### R5：复检参考学习与数值来源

研究时读取授权的人工工程，输出可迁移的条目：

- 当前可观察条件；
- 作者实际处理与可能目的（目的为假设）；
- 相近条件下不同处理的反例；
- 适用/拒绝条件；
- 可自行构造的函数选择及参数含义；
- 支持级别与尚未验证的条件。

研究原件、密集曲线和具体案例留在研究侧。制作侧使用当前歌曲观察、目标时钟及归纳后的条件规则；没有义务每首重新打开全部作者原件。

检查实际执行代码、导入资源、数值参数来源和输入绑定。不能仅凭“编译器没有直接读 research 目录”断言未搬运，也不能用相似度低自动证明原创、相似度高自动判定抄袭。数值相似至多触发来源核查，正常共用的函数和经归纳的候选范围允许复用。

移除或纠正无证据的恒定结论字段，例如无条件写入 `source_or_author_curve_inherited=false`。结果应区分“已登记输入/调用路径审计通过”“发现参考数值直接参与生成”“来源未完全可观察”。现有工具不能证明 Agent 从未看过某条曲线，不得承诺绝对防抄。

新增 Skill 规律须带条件、反例和证据级别；只有同一首改好了，最多记为该条件下的开发经验，不能升级成跨歌曲已验证规律。

### R6：原生/音频复检与交付状态

改变 pitch、音素、分句或声线后，按现有流程重算相关依赖，核对新工程、当前模型输入、波形、拼接、固定增益和无削波。复用已存在的绑定机制，避免再造一套并行记录。

执行状态至少分开报告：

- 条件/元音覆盖；
- 动作实际实现与原生读回；
- 选择依据复审；
- 全曲逐字局部视图与实际审阅覆盖；
- 参考来源审计；
- 实际音频及感知证据；
- 新歌迁移证据。

客观漏项、错误身份、未执行动作或错版本导出阻止“制作执行完成”的声明，但仍保留失败产物与诊断以便继续修复。缺少自然度标签不阻止交付明确标注的候选；缺原生/声学环境时可以完成代码和静态报告，不能声称已经生成或验收相应音频。

不要只输出一个 overall_pass 或用总分掩盖未检查项。阶段内使用 pass/fail/review_required/unknown/not_applicable，适用范围和分母明确；unknown 不折算成 pass。

## 5. 必须接入实际制作入口

采用最小实现，不要求重构成大型 PerformancePlan 系统。推荐在 `src/agent2utau/evaluation/` 补充执行复检模块，并复用原有独立特征、原生身份和哈希检查。

1. 默认整曲制作入口必须消费绑定的条件清单/决策账本，并在编译后、交付前调用共享检查。当前生产用的其它入口也接入；不要无意义重写封存单曲脚本。
2. 当前 helper 和外层函数计划都严格校验字段集合。采用版本化 sidecar 或明确的新 schema/参数；不能直接向旧 JSON 塞字段却声称兼容。为旧 schema 定义清楚兼容行为：可供历史/研究复现，但未经新复检不能获得新的执行完成结论。
3. 独立测量与计划一致性检查分开实现。前者不知道自填 expectations，后者可以使用，但不能将后一项结果直接提升为音乐质量。
4. 产物建议归并为四类：输入/版本清单、逐元音决策账本、独立特征/复检结果、面向人的简短报告及逐字局部图册。复检结果包括 R4.1 的字到视图映射、实际审阅记录和覆盖缺口；图册存在不自动填满审阅状态。文件名由实现决定，关系和 SHA 绑定必须清楚。
5. 更新 Skill 主入口及直接相关 references、docs/workflow.md、必要 README 链接，明确什么时候运行、失败后怎么处理、当前支持到哪一步。删改过时入口说明，避免继续指向已移出的工具。
6. 交付前用实际项目检查最终 USTX；直接编辑、重新编译或后处理使哈希改变后，旧复检结论失效，必须重新生成相关检查。
7. 新报告必须由真实代码结果生成。仅添加报告模板、布尔标记、文字承诺或独立但无人调用的检查命令，不算完成接入。

## 6. 回归与验收用例

针对本次具体风险增加有意义的测试；保留原有适用测试，不追求测试数量。合成测试验证程序行为，不能用作真实歌唱自然度成绩。

| 用例 | 必须观察到的结果 |
| --- | --- |
| 多个真实元音组，仅一条无身份映射的整句泛泛决策 | 缺少逐元音覆盖，不能靠时间覆盖率通过 |
| 有映射但缺主音/主体等必要阶段的决策 | 定位遗漏；阶段必要性按当前语境声明，不强制统一四段 |
| 所有区域均选择有依据的平稳，且连接正确 | 不因波动率为零自动失败；执行与音乐效果分别报告 |
| 明确要求主体展开，实际只有入口大滑音、主体平直 | 主体执行失败，即使全字音域很大 |
| 有限非周期回收或慢中心变化 | 可识别相应运动，不因周期数为零自动判错 |
| 周期组件存在，但被叠加抵消、放错阶段或量化消失 | 检查最终线后发现未达到动作要求 |
| 同元音跨音符、同音换字、AP/SP及短/未知音素 | 归属和分母正确；不伪造重起音、周期或通过数 |
| 写了新动作/字段，实际执行器未消费 | 明确 unsupported/失败，不因计划存在而通过 |
| 移用作者数组/函数参数或加载未登记旧目标 | 在可观察来源链上检出；不可观察部分保留 unknown |
| 原生导出错 SHA、错时钟，或复检后再次修改工程 | 拒绝沿用旧的通过结论 |
| 直接脚本写工程绕开通用编译 | 交付复检仍发现缺证据，不能产生完整执行通过报告 |
| 修改前后的条件变化，如落拍需清晰/同元音延续/主体缩短 | 决策与参数响应可解释；仅更换理由而数值不支持时进入复审 |
| 有全曲总览和少数代表细图，或全图册已生成但部分字未审阅 | 清楚报告逐字审阅缺口，不因图像数量、总览存在或自填总状态而通过 |
| 短字共用局部窗口，长元音跨多个视图，同元音跨音符 | 按真实身份和完整支撑计覆盖，不漏掉页边衔接、不重复计数；保留所需前后文 |
| 局部审阅后修改音高/音素或换成旧版本图册 | 使受影响字及相关连接的旧记录失效；依赖未核实时不沿用通过 |
| 自行构造慢弯折、不对称有限回收、过冲和多次不同转折 | 通过实际选用接口验证时序、方向、节点与叠加后形态，不被统一替换成同形正弦；函数、原生、听感分别报告 |

至少选择一份现有本地生成工程作真实接入回归。旧工程没有新账本时，报告缺失，不能根据最终线倒填“事前决策”；也不能为了展示通过而直接改旧歌。必要时在明确的新任务目录做新的显式设计，分别记录新版本。

测试数据与工具输出不得硬编码《花海》《最后一页》《雨爱》的字数、时码和歌词特判。旧测试中的简化 native mock 应按新契约补全或明确其层级，不把 mock 通过当真实 Core 验证。

## 7. 新歌迁移验收

此项验证用户真正关心的“下一首还会不会退回平线”。代码检查通过和 Skill 写完都不能代替它。

1. 先冻结本次规则与 Skill 版本，登记开发歌曲、已看过的作者目标和待验证歌曲。已见三首不冒充未见曲；同一首换片段最多算较弱的保留片段验证。
2. 从用户本地已有、授权用于当前任务的材料中选一首尚未用于调规则的新歌；若已有正在制作的新歌，优先使用。制作输入不包含该歌作者曲线或由其派生的节点/profile。
3. 先保存条件清单、前向决策和首版参数，再编译、独立复检。记录第一版遗漏/平直候选/有依据的 hold，以及复检后实际修订，不能只报告最终成功版。
4. 若参考已经暴露或验证歌曲被用于继续调规则，标为开发资料；下一次迁移声明需要新的保留输入。不得宣称同一会话不再读文件就等于从未见过。
5. 为检查按条件作决定，使用少量可控的条件变化探针；它们验证分支与执行，不替代真实新歌、完整工程或听感。
6. 当前有整曲制作任务时交付完整工程、全曲逐字局部审阅记录及覆盖结果，不用几个成功片段替代全曲。没有现成授权新歌/原生环境时先完成代码接入及已有资料回归，列出确切缺项，迁移状态保持 unverified。
7. 迁移结果分开写“新歌逐元音执行覆盖已验证”“动作选择有上下文依据”“来源审计范围”“听感证据”。一次成功只证明所测歌曲/条件，不宣称任意歌曲都能做好。

每个新歌首版最多两轮音乐策略修订；常规程序错误修复不受此限制。两轮后仍失败，应提交定位、失败样例和能力缺口，不无限加波、扫参数或把失败歌曲持续调成通过后冒称首次泛化成功。

## 8. Codex 执行顺序与完成标准

按以下顺序直接执行，遇到缺失资源先完成不受影响的工作：

1. 核对当前本地代码、有效 Skill、副本差异及工作区，列出已实现/缺失/变化项。
2. 实现最小身份账本、共享执行复检、独立形态读取、逐字局部视图/审阅覆盖与制作入口接入；明确 schema 兼容与完成状态。先验证现有函数组合能否准确执行所需形态，仅对实际无法表达或转写的部分补接口，禁止静默简化。
3. 补齐第 6 节的风险测试，运行当前相关回归；失败按实际原因修复，不调整音乐判据迎合既有输出。
4. 接入 Skill 和流程文档，用已有本地工程核查实际运行链；核验安装副本并说明会话生效证据。
5. 具备材料时完成第 7 节的新歌验证；不具备时列明缺项，不伪造迁移结果。
6. 提交必要代码、测试、Skill/文档和一份简短完成报告 `docs/skill-execution-review-results.md`。此路径是本轮预期交付，当前尚未创建。

完成报告至少列出：真实执行版本/入口；哪些要求由程序强制检查、哪些仍由 Agent 复审；元音与阶段覆盖的分母/失败/unknown；逐字局部视图及实际审阅覆盖、修改后的复查范围；图示形态的哪些能力已由实际函数/原生路径分别验证；平稳和主体缺运动如何区分；来源审计范围；实际运行的测试和原生/音频检查；首版及修订后的证据；迁移验证是否完成及原因。

发布前遵守当前仓库约定：不上传音频、模型、缓存、run 大数组或本机绝对路径配置；保留作者原件和已接受工程，不改写 Git 历史。报告可引用本地证据的相对位置及哈希，不把本机文件不存在于 Git 误报成已上传。

本轮完成不能只满足“新增了这份说明”或“Skill 校验通过”。最低可交付成果是：检查在真实制作入口被调用、有失败与合理平稳的正反例、输出结论由实际产物支持；未完成的原生、听感或迁移层级明确保留，不吞进一个完成标记。
