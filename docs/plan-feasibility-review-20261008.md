# plan.md 可行性与有效性审查

审查对象：远程 main 的 `d624dc5`，本地已快进拉取。此次只审查计划和检查实际接口，没有执行计划中要求的评价器实现、因果实验或修歌；`plan.md` 和 Skill 未修改。

## 结论

**有条件可行，方向有效，但当前不宜把 READY 理解为“无需澄清即可完整验收”。** 读取实际工程及原生导出、独立测量形态、保留 unknown、不读取设计者 expectations 作为真值，能够补上当前技术验证的缺口。P0 可以证明程序识读、候选风险和反馈定位能力，不能据此证明真假声／口型异常的识别准确率或声学病因。

实施前应明确下面四项，避免实现后报告很完整、评价对象或有效性却对不上。

## 1. 主评测集必须明确

计划第2节和第5节指定白烁三份原件为三首回归输入，却只有《最后一页》另行寻找当前生成版。当前仓库已经包含三份 `projects/latest/*.ustx`，不需要只“尝试查找”生成工程。

建议：**主评测集为三份最新 Agent 工程；白烁三份原件单列只读研究集。** 每个结果绑定 `role` 和 project SHA，不跨角色套用控制计数、音频或问题标签。原作者项目有多个轨道，应按实际轨道角色列出结果；不能把全工程和主唱统计混用。

本次实际读取的差异如下，音符数均为所有 voice_parts 合计，不是主唱字数：

|歌曲|作者原件 parts / notes|当前生成版 parts / notes|
|---|---:|---:|
|花海|3 / 564|38 / 412|
|最后一页|8 / 1208|34 / 412|
|雨爱|2 / 638|1 / 576|

“104 段 VOIC”来自当前《最后一页》的104个非零 VOIC 决策，不是作者工程计数，也不是104条USTX曲线。实际作者《最后一页》有6条VOIC曲线、492个点，无DYN曲线；当前生成版有34条VOIC曲线、34169个点和34条DYN曲线。决策段、曲线、控制点、连续非默认支撑必须分列。

## 2. 把特征验证与听感检测准确率分开

四个时间点是两组对照：87s和184s被反馈为偏假／前顶，93s和176s为偏实。计划H3称“四个声学问题”容易把对照也标成失败，应改为“四个反馈位置、两处异常感受及两处对照感受”。这些是用户给出的相对听感标签，不是一般自然度标签。

八组人工合成测试可以验证周期、边界、单位、unknown等程序行为；不能证明同一指标能识别上述口型／真假声问题。固定无编辑区也不自动等于正常区：无编辑只意味着没有施加本次扰动，原有问题仍可能存在。

建议分开报告：

- 合成程序真值上的特征误判、漏检及 unknown；注明样本数和分母。
- 明确用户标签范围内的候选定位命中及对照响应；四个粗时间点不足以估计整曲误报率／漏报率。
- 未标注真实歌曲区域的候选数、覆盖率、unknown与待审核数，避免称为假阳性／假阴性。

阈值、窗口、去趋势方法和极值显著性应预先固定在配置中；开发样例与保留样例分开。规则波动和变化波动都只输出特征，不用“规则=机械=坏”的捷径。相关性也不能给出共鸣或发声病因。

## 3. 原生导出要增加可校验的绑定契约

现有桥接已提供实际 before-PITD、最终 pitch、物理毫秒、音素时钟和ownership，适合本轮。**这些是渲染器重采样前的意图线／音素时钟，不是音频实测F0或声学对齐。** 导出JSON本身含工程路径，但没有工程SHA或完整声库／软件状态；仅有文件名与相同歌词不能证明对应当前工程。

建议显式输入一个 provenance sidecar：绑定工程SHA、两个导出SHA、桥接/Core及声库身份、采样单位与时基；核对part/track、note身份及几何。绑定不匹配应拒绝或unknown，不能照常统计。测试增加错版本导出、错单位、时间非单调、ownership歧义及数据长度不一致。

本机已核实反馈音频SHA为 `35f301641b4cacbf5baff0c52ae7db8b8e72291a2d1573b85ae8d6aee0463789`，与交付检查及反馈记录一致。当前工程SHA为 `a17d4bebdd3c5951f2b10138777a8fee8925ab5beb6bb70705342d1b6ba466af`。它们的绑定可用，但不能把新的作者重渲染或其它片段冒称这条反馈音频。

## 4. 缩小相位探针与声学有效性的首轮承诺

当前 `export-pitch` 固定在5 tick网格，没有任意采样相位参数。单份导出能报告该网格的观察；不能证明网格间没有尖峰。计划将缺Core标为 requires_native_probe 是合理的，但**有一份Core导出也不等于多相位已检查**。

建议v0先将未覆盖的多相位风险标为 `requires_native_probe`，除非实现另行核实了真实Core重采样路径和相位接口。不通过移动唱字、改tempo或改变音素几何来伪装为相同输入的相位检查。

口型／真假声问题的已证实原因不能由pitch极值或TENC/BREC相关性推出。本轮接口与单因素实验提案有价值；实际声学有效性仍需对齐到具体音素和音区、冻结条件、无变化重复对照，以及有效音频评价。F1/F2或频谱代理也只能提供候选证据。

- 原始三份作者文件与manifest SHA一致；当前三份生成工程均可解析。
- 当前测试基线：`python -X utf8 -m pytest -q`，52 passed。
- 对仓库中的当前《最后一页》重新执行 `export-pitch` 和 `export-phonemes`，34个原生上下文成功；fresh pitch数组与交付导出逐项相同，工程文件SHA未改变。没有渲染音频。
- 四个粗时间点都有唯一原生phone命中：87s `zh/uo`、93s `zh/ir`、176s `zh/zh`、184s `zh/ao`。176s是声母，其余位置也有不同音素／音区条件；定位应保留前后唱字语境。它们是原生时钟候选，不是已证实声学病灶或共振峰测量。
- 原生音高、音素导出及反馈音频在本机可用；这些音频和run产物不在Git中。只有Git资料的环境仍应按计划交付静态子集与missing_data。

本次核查日志、输入哈希与详细只读清单保留在本机 `runs/plan_review_20261008`，不提交音频或大数组。尚未实现独立评价器，因此没有新检测器的精确率、召回率或自然度结果。

## 建议的P0验收边界
