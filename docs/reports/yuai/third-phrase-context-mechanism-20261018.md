# 当前模型确实依赖上下文；第三句听感病因尚待隔离

用户最新否决Q并提出模型预测/上下文怀疑，已追加[原话与范围](../../../songs/yuai/reports/legacy/third-phrase-Q-rejected-context-question-20261018.md)。当前工程Q不再标听觉待评，而是已被整体否决；本条没有新的虚实/气声/暗挤分轴标签。R先前“更贴耳、和前两句感觉不是同一个状态唱出来的”保留其原版本/比较范围。用户怀疑是需要检验的因果假设，不能直接写成已证实的模型缺陷。

## 1. 是的，同一模型会受上下文影响

本机当前variance语言编码器实际输入为tokens、languages、ph_dur，输出encoder_out；ONNX含4个Softmax及时间卷积等结构。后续variance模型读取整个原生段的encoder_out、音素帧时长、逐帧pitch、speaker、步数/retake等，输出breathiness_pred、voicing_pred、tension_pred。声学模型还读取当前段的音素、时长、F0、speaker和这些最终发声特征。因此不止当前字、当前音高或当前UI值决定结果。

人工BREC/VOIC/TENC是加到预测基底上的偏移，再按模型范围裁剪；相同曲线值不等于相同最终发声。DYN在声学输出后改变包络，不能用它校正预测的音色/演唱状态。较接近的三通道中位数亦不能证明其它高维声学条件等价。

当前前四句实际分成7个原生预测上下文。第三句单独分为“下雨了”（约26.581–27.942秒）和“雨陪我哭泣”（约28.498–31.650秒），各有自己的padding与编码/预测；同一轨道、同一个片段不等于共同的模型上下文，模型也不会因界面上连续摆放就自动继承前两句的演唱状态。此前换库参考主唱的第三句与第四句前半在更长上下文中，是已查明的条件差异，不是已查明的音质因果。原生上下文与词/音乐句边界应分别记录。

官方实现同样体现按RenderPhrase组织语言编码及variance预测：[DiffSingerVariance](https://github.com/openutau/OpenUtau/blob/master/OpenUtau.Core/DiffSinger/DiffSingerVariance.cs)、[Renderer](https://github.com/openutau/OpenUtau/blob/master/OpenUtau.Core/DiffSinger/DiffSingerRenderer.cs)。官方当前网页仅作机制旁证，本机事实以已绑定实际模型与导出的模型输入为准；不把上游偏好字段当作本机可用的工程控制。

## 2. 已用当前实际模型做确定性编码检验

本轮不是只据文档推测。直接加载当前声库实际解析路径的 `0801_variance.linguistic.onnx`，在CPU执行现有第三句两组精确输入，先重现原生缓存encoder_out，再将两段自身序列以当前静顿的48帧SP连接成一个语言编码输入。原有16个中心音素的token、ph_dur、language逐项精确，只有其周围上下文/边界和整段形状改变。

原始两段重现缓存的最大误差均小于1e−4；同一输入重复两次输出精确。联合输入重复输出也精确，当前语言模型无随机节点。上下文改变后6/6与10/10中心音素的编码均变化，最大绝对latent差约0.4311/0.2339，RMS差约0.0851/0.0543。它们只是未解释的潜在编码单位，不能换成气声、实度、距离或dB；16/16发生变化亦不表示声音一定有可辨差异。

这**实测证明当前语言编码对上下文敏感**，不能证明后续variance、声学输出必然朝某一方向变，或“贴耳”就是由此造成。本轮没有运行variance/acoustic/vocoder，没有生成音频或将诊断合并输入冒称OpenUtau原生工程分句；gap仅按观察静顿量化到诊断帧，实际工程/phone时钟没有变化。也没有复制参考文本或曲线作为生产目标。模型/配置与精确输入、输出NPZ和复现误差在本轮run绑定。

当前variance图另含RandomNormalLike。它提示后续对照须控制随机采样或先做重复基线，不能把任意两次输出的差异都归因于上下文；缓存还可能使相同输入复用旧结果。本轮确定性语言编码差异没有这个混杂，但没有因此宣称已控制variance随机性或需要重装/重训模型。

## 3. 前几轮判断的实际缺口

此前查实了声线、人工增量、实际输入和工程版本同步；这些只能证明控制生效及对照范围，不能证明预测基底的演唱状态适合当前句。已发现自己与参考原生上下文不同，却在R/Q轮仍优先替换声线/发声处理，没有先检验这个输入条件。R和Q均被否决，继续将问题等同于VOIC不足、气声未减够或比例未选对，没有现有证据支持。

这里要调整的是诊断顺序：当前优先检查上下文、预测基底及声学层贡献，停止新增人工剂量。不能把“上下文可能影响”升级为“合并越长越好”，也不能把已完成的编码对照说成第三句演唱问题已解决。

下一有限检验应保持中心唱字身份、目标时长/F0、speaker、人工控制及增益，比较分段/联合上下文下的预测；先安排可比较随机条件/重复，分开语言/variance变化与声学上下文变化。若原生AP/SP干预连带改变phone几何和before-PITD，必须重新导出并逐项记录，不能继续声称所有时钟保持或照抄旧PITD。最终需要当前工程中可查看、完整邻句语境的成声对照，听觉验收仍由用户反馈提供。
