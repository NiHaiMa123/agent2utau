## 2. 名称相同之外：实际声库文件和声线是什么

### 本机b目录实际上链接到c

`Singers/YousaV1.65b` 是指向 `Singers/YousaV1.65c` 的目录junction。路径解析、character/dsconfig及声学/variance模型文件SHA均相同。当前工程ID仍是b，本机真正读取的是该链接指向的文件；本轮没有建立或修改链接，也没有将其当成错误自动修复。

因此，在本机当前状态仅切换b/c名称不能被当作独立模型实验。旧原件yousaV1.56仍缺失，旧作者声音也未提供，但这不妨碍计算当前已经换库的白烁轨道。此前以“旧库缺失”限制了对当前对照轨的核查，范围不完整。

### CLR和clNN并非同一套索引

当前加载的CLR选项顺序是：Bright、Classic、Cute、Normal、Whisper；CLR=3对应Normal。模型/subbank的clNN顺序则是：

|曲线|声色|
|---|---|
|cl01|Bright|
|cl02|Cute|
|cl03|Normal|
|cl04|Whisper|
|cl05|Classic|

cl05=35只指定35%Classic，剩余65%由当前音素的默认suffix补足；不是默认65%Normal。我们的唱音素显式CLR=3，当前白烁参考没有相同的CLR指定，加载后实际suffix为Bright。

CLR还参与音素时长模型的按phone声色选择；clNN主要是后续pitch/variance/acoustic的帧级混合，不能把cl05比例直接当成时长模型同样采用的混合。当前两边时长模型的默认phone声色分别是Normal与Bright，这也是需要分开的预测条件。

此次直接导出当前Core两阶段speaker embedding，并在各自模型空间用五个实际`.emb`文件独立重建。矩阵秩5、重建误差在浮点容差内；我们14组阶段embedding与已绑定原生实际输入逐项精确。得到：

|声部/音乐句|实际声线（唱元音帧）|
|---|---|
|我们第一句|Normal65%＋Classic35%|
|我们第二句|Normal100%|
|我们第三句P|Normal65%＋Classic35%|
|我们第四句|Normal65%＋Classic35%|
|当前白烁主唱前四句|Bright41%＋Classic59%|
|当前白烁和声|Bright100%，但保存为静音|

**两边没有使用同一发声基底。** 这是当前实际条件差异，不是“Bright必然更实”或“59是正确比例”的证明。我们的第一二句声线不同却获相对一致反馈，第四句也获局部认可，明确反驳“参数必须全部相同才一致”。

## 3. 各参数逐项的实际路径

本次覆盖当前36项表达声明、原件31项，逐项清单见[完整参数CSV](../../../songs/yuai/reports/legacy/first4-full-parameter-audit-20261018.csv)。其中当前原生副本加载34项，16项被DiffSinger声明支持，18项不在本引擎支持集中；另2项是空的masked声明。**支持不等于非默认执行，也不等于当前模型启用了该分支。**

|参数/字段|实际作用与单位|本次关键边界|
|---|---|---|
|tone / tuning|记谱MIDI及音分微调；也参与音素/模型条件|前四句31个唱字中心全部对应；tuning均为0或原件省略的默认0|
|note.pitch.data.x / y / shape / snap_first|x为相对音符的毫秒，y每单位10音分；连接形状和前字承接参与before-PITD|不能只看PITD点，或把原生before-PITD当艺术目标|
|PITD|音分偏移，最终线=原生before-PITD＋PITD|当前声明±2400，原件±1200；声明范围不是已使用幅度。大起伏不证明实感|
|内置vibrato|length为音符时长百分比，period为ms，depth为音分；in/out/shift/drift控制建立、退出和相位|我们前四句内置length均0，周期写在最终目标中；参考末“清”另有内置vibrato，必须叠加看|
|vibrato.vol_link|有内置vibrato时可联动波形增益|本段两边均0，不能用它解释局部忽大忽小|
|CLR / cl01–cl05|CLR选择音素默认声色及相关时长条件；clNN参与后续帧级混合|两种索引及作用阶段不同；已实际核实variance/acoustic中的Bright/Normal余量|
|VOIC|`clip(pred+(value−100)×0.12, −96,0)`|100为零人工增量，不是没有有声成分；200不是“200%实声”。模型单位不是输出dB或闭合商|
|BREC|`clip(pred+value×0.12, −96,0)`|0保留非零预测；−80平台是约−9.6特征单位，不是降低9.6dB的真实气声|
|TENC|`clip(pred+value×0.05, −10,10)`|0并非零张力；参考末“泣”7只加约0.35特征单位，不直接等同唱歌力度|
|DYN|值×0.1dB的合成后振幅增益，最低声明值有特殊静音语义|P写回为5≈+0.5dB，包含已听整句匹配条件；不是生成实感的旋钮|
|GENC|key-shift/gender嵌入，由模型augmentation范围换算|本段实际输入0；不是将遗留GEN旗标直接送入模型|
|SHFC|音分条件偏移，影响variance及特定acoustic F0条件路径，vocoder另有路径|本段0。不是PITD同义词，−4也不是−4半音|
|VELC|速度嵌入`2^((value−100)/100)`|本段100，实际velocity=1；与旧VEL的辅音伸缩不同|
|ENE|模型energy嵌入分支|渲染器支持声明存在，但本模型`use_energy_embed=false`、`predict_energy=false`，无energy输入|
|PEXP|调用pitch模型时的表达性输入|默认100不自动给当前人工PITD增加表达；本轮没有pitch重新预测/采用|
|VEL|传统音素时序提示|当前DiffSinger未确认消费该伸缩量；作者写100也只是默认，不是强字处理|
|VOL / ATK / DEC / OPE|传统采样引擎包络/开口参数|本DiffSinger不支持该phone envelope路径。参考常写ATK100/DEC0，不能称隐藏的字头发力/释放配方|
|GEN / BRE / LPF / NORM|传统resampler旗标|在本引擎中不等于GENC/BREC；NORM86默认也不是当前人声被自动归一化|
|ENG / ALT / SHFT / DIR / MOD / MOD+|传统采样器、别名、条件查询/调制或其它引擎路径|本段没有相应DiffSinger消费者，不能按名字推声学作用|
|CLRY / XSY / GRWC|其它合成/引擎的交叉合成或growl能力|当前DiffSinger不支持，不能作为当前“磨砂填充”已启用证据|
|RPIT / PITO / masked_curves|版本相关的渲染/覆盖数据机制|当前载荷为空，兼容原生副本移除这两项空声明；不是本段隐藏覆盖线|

## 7. 和声、轨道增益和模型状态的边界

参考后半第三句确有高声部“雨陪我哭泣”，其MIDI68/64/66/68/71对应主唱64/61/63/64/68。但当前组合工程中和声静音，因此**不能用原件曾有和声，解释当前默认单独白烁主唱的厚度**。打开和声后的作品效果另是一种比较条件，也不能代替主唱实感验证。

当前自己的7段原生variance缓存均能按精确输入键读取，三通道原始预测与已绑定实际输入重建一致；14组speaker embedding也逐项一致。当前参考的完整上下文未找到匹配的既有linguistic缓存，因此参考的当前三通道预测/最终acoustic输入保持unknown，**没有为填补数据新运行预测或合成音频**。本轮确定的是加载后的实际声色、原生最终线/phone/控制采样与计算上下文，不伪称参考真实PCM或历史模型状态已经恢复。

这个缺口不能用“VOIC114比我们的180小，所以肯定更虚/更实”填补。也不能以我们自己的代理指标推断Bright/Classic参考的音质。当前用户听感仍是主要验收证据，尚没有通用、可反算剂量的虚实评分器。

## 8. 这次应怎样修正判断顺序
