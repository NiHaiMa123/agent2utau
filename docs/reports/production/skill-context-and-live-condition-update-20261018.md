## 为什么需要更新

现有Skill已要求逐句设计、AP/SP后重导音素/before-PITD与两阶段预测、分轴反馈及原生speaker核查。此次执行仍先在旧上下文里反复调声线/人工控制，未将呼吸/计算上下文作为发声校准的前置条件；加载时的CLR映射与导入曲线映射也未被纳入现场试听身份。缺口是决策落点和条件核对，不能再写一套“多减气声/多加实”配方。

本次来源：[AP/SP原生结构消融](../yuai/apsp-context-link-audit-20261018.md)、[当前语言编码上下文检验](../yuai/third-phrase-context-mechanism-20261018.md)、[前三句AP/SP候选](../yuai/first3-apsp-context-candidate-20261018.md)、[实际App重映射处理器核查](../yuai/voice-remap-dialog-audit-20261018.md)、[当前目标来源复核](../../../songs/yuai/reports/legacy/first3-apsp-provenance-recheck-20261018.md)。都按原有证据范围使用：分段改变/编码依赖不证明声音好，“好像好了”的对象仍未澄清，现场我们轨道重映射内容仍unknown。此次不新造试听标签或倒填接受。

## 五份实际修改

1. `SKILL.md`：主循环加入源观察后的呼吸/计算上下文选择；发声校准前直接路由到AP/SP原生分句与实际加载条件检查，不再只在末端专项列表中出现。
2. `references/phrase-by-phrase-workflow.md`：先决定当前自己时间轴的呼吸/静顿/保留空白，导出音乐句→RenderPhrase映射，再在最终pitch/phones/speaker/上下文下检查预测和写剂量；逐句制作不等于每句独立预测，不因同轨就认为状态连续。既有逐句音乐设计和编译契约保持。
3. `references/ap-sp-placement.md`：补显式标签、隐式SP、padding与跨段可见性的区别；有限标签/留空由当前条件选择，不铺满空隙、不要求整曲一个模型段或更长必好。检查旧控制平台/尾部在新增AP/SP真实帧上的取值，存储节点不变不代表非唱中性；上下文重算的phone、载频、随机形状与输出电平分别记录。
4. `references/voice-baseline-and-stability.md`：三类参数比较前先查计算上下文和实际加载。区分磁盘/自动保存/实时内存，以及CLR音素映射/导入曲线到clNN转换；按实际源参数、节点、目标曲线与消费者判断，不因弹窗标题就认定全轨变色，也不认定确认后必无影响。现场不可观察保留unknown，可继续范围明确候选，不另加人工许可门槛；用户指定工程试听时，不能只交新音频而留旧工程。
5. `references/planning-and-evaluation.md`：区分新音乐设计、保持自有目标与重编码，绑定实际读入来源；不能把点数增加当从零画线，也不能把有过参考研究说成从未参考。保留初步/指代不明的反馈，不凭编码/特征/分段数量升级同一演唱状态或处理因果。

没有将本曲标签数、时码、混合比、控制剂量或观测幅度写进Skill，没有新增“AP/SP改善虚实”的已验证通用结论。加载提示的当前具体ene误识别实现保留在项目报告，Skill只写核对参数类型/内容/应用分支的方法，不把某版本缺陷写成永久规律。
