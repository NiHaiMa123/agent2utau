# Skill改为逐句制作（2026-10-16）

按用户“改skill流程，和真人画线一样，一句一句做”更新仓库Skill并同步安装。仅单Agent，本轮没有修改歌曲工程、音频、模型或生产代码，没有新渲染或远端CI。

## 当前流程

先通览整曲并列音乐句。对当前句依次完成：连续原曲/歌词/音素观察 → 逐字及延续阶段构思 → 本句意图前置冻结 → 只画本句 → 原生落线与完整主体/跨字复核 → 当前成声及输入依赖检查 → 保存进度，再进入下一句。整曲最后组装已复核的逐句目标，另查跨句和整体强弱；不先给全曲填入口偏移和平台。

新增[逐句流程](../../../skills/singing-expression-editor/references/phrase-by-phrase-workflow.md)，主入口、整曲重画、条件到函数、计划与评估、工具接入、执行契约及项目workflow同步指向这一顺序。进度建议记录pending/working/ready_for_next/needs_revision及绑定产物；听觉状态另列，不要求用户逐句批准。现有明确漏画/动作失败不能写成ready；允许未知条件下明确艺术候选和用户要求的缺口交付，不把流程变成无休止等待。

入口、主体和退出的独立音乐主张各自检查。现有检查器一个gesture中至少一项能否决浅对照即可，因此多个独立主张须拆开，不能只检查几个入口点就让整句通过。主体稳定有理由即可，不统一最低波动，也不要求每字加颤。逐字图审写具体观察，不把整句评语重复填给全部字。

## 接口边界

当前compile-functions只接受scope=whole_song及其输入工程的完整覆盖，尚无phrase范围或逐句顺序自动门禁。新Skill明确用保持绝对时钟和必要上下文的当前句工作副本走现有契约；提取、回写均须核原生音素/时钟、授权区等价和区外保持，邻接依赖改变则复核相关句。不能声称新增进度文件已经被CLI验证。整曲最终可批量做确定性编码/渲染，但不能重新批量设计或给未完成句补平台。

同时纠正旧整曲页“清空旧note pitch”的接口表述：现有编译器保留note.pitch、清除输入副本PITD及内置vibrato贡献；实际修改范围应按所选基底和用户授权登记。

- 静态反例复核：原整曲第一句只有入口landmarks，未约束气后段，按新流程不能据此判主体设计完成；新单句有窗回探/气后段的独立后果检查，但天的浅起落还不能仅凭事后helper期待追认成新流程已执行。两者旧锁和收据不改、不倒填。
- 合法稳定字可以hold并保留上下文理由；连续元音跨界不能为切句制造停顿；用户没有每句反馈不妨碍Agent在已授权范围内自主逐句继续。上述为方法与现有产物的静态检查，不是新曲前向行为验证。

当前完成的是Skill工作流程更新。真实后续制作必须实际按句推进并留下当时记录；是否改善音乐和跨曲效果仍需制作与试听验证。本轮未重做雨爱剩余句子。原字节、安装核查和保护范围见同名JSON引用。
