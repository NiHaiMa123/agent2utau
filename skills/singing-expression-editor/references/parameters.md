# 参数与演唱意图

所有参数关系都要绑定当前OpenUtau版本、YousaV1.65c及模型条件。下表是项目已核实的操作意义和待检验的表达用途，不是“情绪→常数”的处方；有效范围从原生表达声明读取，不从旧统计或研究边界推导。

| 控制 | 项目中的实际作用 | Agent应判断的条件 | 常见误用 |
|---|---|---|---|
| 连续目标pitch | 谱面中心加进入／主体／周期／恢复；也进入variance与声学模型 | 音程、时值、元音、音区、乐句角色、源动作可信度 | 每音强制波浪；复制原唱噪声；用少暴露高音掩盖错误 |
| PITD | 相对实际before-PITD曲线的偏移，不能只扣音符中心 | 目标线在编辑器／合成器中的实际基底与单位 | 同时写note pitch和PITD而重复相加；扣旧基底 |
| 起音／换音 | 动作的位置、支撑、斜率和形状由函数执行 | 连／断唱、声母到元音、前后音程、目标音区 | 每次固定下探或过冲；用曲线中心冒充生理锚点 |
| 主体走势／颤音 | 慢走势与周期项分别安排，周期含进入／退出包络 | 长短音、强弱走向、延音作用、周期支撑、声库表现 | 从第一个采样就等深度正弦；加大深度处理音色或attack问题 |
| DYN | 合成后输出增益；当前实现值×0.1dB | 句内强弱目标、实际音频能量、可靠元音与未知区 | 把每字归一到一样响；复用旧pitch的增益曲线 |
| VOIC | 调整声学发声特征，不是纯输出音量 | 在受控探针支持下选择发声方式 | 小声就盲目加VOIC；把特征单位当输出dB |
| TENC／BREC／SHFC | 当前声学模型的张力／气声／音色等条件控制 | 音区、元音、句子角色与已有响应试验 | 高音必加张力；直接照搬其它声库或SynthV数值 |
| CLR／clNN | 音素声线与声线混合；索引约定不同，实际speaker进入多个模型 | 目标声库中的整曲基底、参考机制迁移、何时允许有目的变化、全通道检查 | 每句随机切换；只检查一个通道；跨曲／换库盲用同一混合常数 |
| 音素时长 | 影响可懂度、元音承载、pitch与variance条件 | 对齐证据、声母／元音的真实目标时钟 | 把HFA源时钟当合成时钟；用最短音符掩盖坍缩对齐 |

当前声库未启用energy embedding／predict_energy，ENE不是现有可用的响度解法。核对安装状态再使用，不因有同名参数就假设有效。

要实际规划非 pitch 曲线，读[多通道发声与长音阶段](joint-phonation-and-sustain.md)。区分写入值、加载后有效值、工程表达声明、模型增量与最终输入。VOIC=100在已核实接口中为零人工增量，不代表固定预测能量或引擎硬上限；已存自定义表达范围可能被原生加载保留。需要增强时可明确设计本工程的合法范围，先检查加载与采样确实保留，再记录模型特征裁剪和未实现部分；不能直接迁移旧工程数值或偷偷越界。具体流程见[音高、预测发声与响度](pitch-phonation-and-loudness.md)。SHFC 在当前原生中进入条件 pitch 的不同路径，不能简单解释为PITD、纯响度或无依赖的音色旋钮。

当前工程的 `phoneme_expressions` 中 `index: 0` 的 CLR 只指定第一个音素，后续音素可能采用默认声色。检查原生 phones 的 suffix、实际音素时钟，以及 variance／acoustic 两阶段的 spk_embed；不能从一个音符显示 Normal 推断整字或整句都是 Normal。clNN 可覆盖实际混合；全零曲线不等于静音，也不能不检查默认音素声色便当作纯 Normal。声库迁移按名称映射索引后，仍需重新核对这个作用范围。

强弱不稳定时按[声线基底与稳定性](voice-baseline-and-stability.md)分别检查声线、发声表达与输出包络。用户明确接受的整曲听感不能由仍有声学能量落差否定；反馈绑定确切音频，不能迁移到新输出或当通用比例。

动作选择需要能解释机制。若疑似音量问题，先区分输出增益、字内包络与声学发声状态；疑似高音撕裂时同时比较目标轨迹、实际F0、声学状态和音区响应，不能单凭一个峰删音符。语义重音只提出候选意图，不要求pitch／张力／响度同时增加。

具体强调位置、力度包络与独立对比方式见[强调选择与加强方式](accent-selection.md)。局部参数生效及音频量变化只能支持该次响应；局部“不明显”反馈不能证明整曲任何位置都无效。

响应知识条目至少包括：声库／模型哈希、音区与音素条件、单次控制变化、同条件／同噪声基线、实际音高／能量／谱形变化和未排除因素。没有此类依据时标为待验证关系，不伪造“已掌握的白烁规则”。
