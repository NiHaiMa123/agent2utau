# 设计前使用表1、表2

用于新曲、重制、修订和局部试听迭代。表1说明对象与控制机制；表2保存有条件的处理、实际响应和用户反馈；Skill保存可复用的方法。先判断已有经验如何约束本次选择，再设计新参数，不把每次制作变成重复盲试。

## 找相关证据

在项目根读 `docs/guides/knowledge-use-in-production.md` 和当前 `docs/knowledge/acoustic-manifestations-20261009/active-knowledge-sources.json`。这是项目知识接口；路径不存在时定位项目明确指定的等价目录，记录缺失，不从其它歌曲的工程或缓存代替。

检索以当前任务的问题、实体、控制机制和条件为线索，例如虚实、强弱、音高入口、音素时钟、尖挤与层次。查看当前索引中的相关系列及后续反馈、更正、接受范围；不要只读最早总结或只选有利例。作者研究形成的公开方法/反馈结论与作者目标曲线是不同资源。

检索范围应在当前run留下可检查的记录，可用 `knowledge_coverage.json` 或计划说明：

- 问题/检索线索、实际查看的索引或报告及SHA，相关记录ID。
- 相关正例、阴性、副作用、撤回/更正和仍unknown的范围；没有某类证据时说明实际检索结果，不补造。
- 本次如何使用、为何不适用或只能外推，以及它具体改变了哪个先后顺序、设计决定或验收要求。
- 未覆盖或因用户边界未读取的来源；无匹配结论时保留缺口，给出当前自主候选，不默认扩大研究或停工。

记录检索覆盖是Agent声明，不是自动证明检全。当前 `knowledge-context` 与编译门禁只检查所选来源/字段/SHA和逐ID决策，不能发现所有漏选经验，也不能判断应用是否正确。不能用“包通过”代替以上检查。

## 带入当前设计

执行 `knowledge-context`，保存新SHA绑定上下文和逐ID `use/reject/extrapolate/keep_unknown` 决策，在函数编译前接入。已有上下文、意图和receipt不事后刷新；新反馈追加公开记录并更新当前来源目录，下一版使用新的上下文。

当前任务禁用历史制作数据时，可建立只含允许公开知识的显式目录，说明被排除的制作载荷。除用户明确连知识结论也禁用外，这个边界不等于忘掉已学方法、阴性或副作用。不得为读取反馈继续打开其链接的旧工程、函数节点、控制数组、预测、波形或作者原件；不把旧剂量、时码或目标线迁移进新作品。

已有局部接受只约束当时条件。新音素、音区、语言或全曲应用标为外推；“相对最好”与“可以采用”、组合有效与单因素有效分别记录。更正撤回的问题停止修复；无差别/否决的候选不因数值有变化自动加码。

虚实问题先核对源音乐阶段、词/辅音/元音与原生实际时钟，再检查当前预测基底及发声选择；不得默认以增益或某个通道补偿。虚实、发力、磨砂填充、尖挤与数字响度分开。改变音高、音素或speaker后重建实际输入和成声，整曲强弱另行核对；已学方法不保证当前声音通过。

## 何时再研究

优先用已有经验制作、提供有区分力的早期试听，并随逐首反馈补表。只有当前实际输入和明确听感暴露了现有证据不能处理的具体问题，才提出有限新对照，说明它能区分什么。不要为知识未完全泛化而重复大规模扫参；磨砂质感的可靠控制映射、跨曲迁移等未解决问题保持unknown，不阻塞已授权的候选交付。
